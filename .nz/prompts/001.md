❓ Q4 — Meaning of “Handy should no longer appear”: Should we enforce a controlled exception list, or attempt a literal zero-match repository?

A literal zero-match would require corrupting or disguising valid names and historical facts such as:

- handy-keys, an upstream dependency and serialized setting name
- handy-computer/* Hugging Face repository IDs
- blob.handy.computer download URLs
- old storage identifiers needed by any compatibility code
- upstream GitHub links and license attribution
- historical release notes and dependency lock metadata

➡️ Recommended answer: Adopt a narrow allowlist. Permit “Handy” only for:

1. Explicit foundation credit and upstream links
2. External proper identifiers that Dictum does not control
3. Dependency and lockfile provenance
4. Legacy compatibility constants and tests
5. Historical material deliberately retained as history

Everything owned by Dictum—including code symbols, event names, package names, UI strings, executable names, environment variables, and current
documentation—should use Dictum terminology. Add an automated audit so every remaining match is intentional.

❓ Q5 — Brand character: What should “Dictum” communicate visually?

The name could credibly support several directions:

- Formal/legal: authoritative, traditional, institutional
- Corporate/technical: precise, restrained, modern
- Voice-oriented: speech, waveform, microphone, transcription
- Abstract: a distinctive symbol without literal speech imagery

This choice is the prerequisite for the icon, wordmark treatment, typography, and exact blue palette.

➡️ Recommended answer: Corporate/technical with a subtle voice motif: precise, calm, authoritative, and modern—not legalistic, playful, or AI-
glowy. Use a simple geometric mark that remains legible at tray-icon size.
